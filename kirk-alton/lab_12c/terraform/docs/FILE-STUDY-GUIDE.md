# Terraform File Study Guide

Each row explains why the file exists, how it connects, and what to watch while studying or changing it.

| File | Purpose And Integration | Important Ideas / Arguments | Common Mistakes And Troubleshooting | Security / Production Notes |
| --- | --- | --- | --- | --- |
| `00-providers.tf` | Sets Terraform/provider compatibility and configures AWS. Every AWS resource uses this provider. | `required_version`, provider source/version, `region`, `profile`, `default_tags`. | Provider initialization failures usually mean network, credential, or version constraints. Run `terraform init -upgrade` deliberately, not casually. | Provider upgrades can change schemas. Review release notes and commit `.terraform.lock.hcl` in a real project. Avoid static credentials in code. |
| `01-backend.tf` | Selects where Terraform state lives. No enabled block means local state. | Backend arguments are initialized before normal variables and cannot use `var.*`. | After changing backend configuration, run `terraform init -reconfigure` or `-migrate-state`. Never enable two backends. | State contains passwords and client secrets. Shared work needs encrypted remote state, locking, versioning, and narrow access. |
| `variables.tf` | Declares the public inputs to the root module. | Types, defaults, descriptions, validation, `sensitive`, and nullable `alert_email`. | A missing `test_user_password` is intentional. Put it in ignored `terraform.tfvars` or an environment variable. | `sensitive` redacts CLI display; it does not remove a value from state. Production users should not be lifecycle-managed with passwords in Terraform. |
| `locals.tf` | Centralizes normalized names, tags, and the API's required Cognito scope. | `lower`, interpolation, common tags. | Renaming `name_prefix` can force replacement of named resources. Review the plan carefully. | Stable names aid auditability. Separate environments should also use separate state. |
| `naming-helpers.tf` | Adds uniqueness only to the Cognito prefix domain. | `random_string` persists in state after first creation. | Removing/replacing the random resource changes the public login domain. Cognito domains reject reserved terms. | A custom domain is preferable for production trust and branding. |
| `aws-helpers.tf` | Reads the active Region, account ID, and AWS partition. | Data sources are read during plan/refresh. | If these fail, check the selected profile and AWS credentials. | Partition-aware managed-policy ARNs work in commercial, GovCloud, and China partitions where services are available. |
| `cognito.tf` | Builds the identity boundary: pool, app clients, managed login, and test user. API Gateway trusts the pool ARN. | MFA, `user_pool_tier`, `sign_in_policy`, schema constraints, auth flows, token validity units, OAuth callback/scopes, `generate_secret`, branding version. | Required schema attributes are effectively immutable. `ALLOW_USER_AUTH` needs supported pool/client settings. Managed login needs a domain, callback, OAuth settings, and branding. | Require MFA, hide user-existence errors, protect secrets/state, and use real onboarding/recovery policies in production. |
| `dynamodb.tf` | Stores token-use metadata consumed by the helper, routes, and detector. | String partition key, on-demand billing, SSE, point-in-time recovery. | Declare only key/index attributes in Terraform's `attribute` blocks. A scan becomes costly at scale. | Store token IDs/metadata, never raw JWTs. Add TTL, deletion protection, backup and a more scalable access pattern for production. |
| `iam-policies.tf` | Defines narrowly scoped actions for route updates, detector scans, and scheduled invocation. | `aws_iam_policy_document`, exact action lists, exact resource ARNs. | IAM “AccessDenied” errors usually indicate the wrong role, action, table ARN, or delayed propagation. | No wildcard data-plane resources and no unused Bedrock permission. Periodically review managed and customer policies. |
| `lambda-roles.tf` | Creates service trust policies, execution roles, and policy attachments. | Service principals, `sts:AssumeRole`, AWS-managed basic logging policy, separate role per responsibility. | Trust policies answer “who may assume”; permission policies answer “what may it do.” Mixing them causes confusing failures. | Separate roles reduce blast radius. API Gateway's CloudWatch role is account/Region scoped and needs coordinated ownership. |
| `lambda.tf` | Packages local source and deploys the three functions. | `filename`, `source_code_hash`, handler module/function, runtime, environment variables, timeout, dependency ordering. | Handler names must match ZIP filenames/exports. Archive changes must alter `source_code_hash`. IAM can take time to propagate. | Pin/bundle SDK dependencies and publish versions for production. Environment variables are configuration, not secret storage. |
| `api-gateway.tf` | Builds the REST authorization boundary and two Lambda proxy routes. Publishes a deployment to `prod`. | `COGNITO_USER_POOLS`, `authorization_scopes`, `AWS_PROXY`, integration POST, Lambda source ARN, deployment trigger hash, stage logs. | A REST API change is invisible until redeployed. Integration method is POST even when the client method is GET. A 500 often means missing Lambda permission. | Access-token scope checks happen before Lambda. Keep data tracing off around tokens/PII. Add WAF, throttling, custom domain, and stricter resource policy as needed. |
| `eventbridge.tf` | Invokes the detector on a rate expression. | Scheduler uses a target execution role and `flexible_time_window`. | EventBridge Scheduler is not the same resource as classic EventBridge rules. Check role trust and `lambda:InvokeFunction` on target failures. | Add DLQ/retry policy and monitoring for production schedules. |
| `monitoring.tf` | Makes logs finite-lived and converts detector alerts into a metric, alarm, and notification. | Standard log class, retention, literal filter pattern, `Sum`, missing-data behavior, SNS KMS key. | Filters are not retroactive. Email subscriptions remain pending until confirmed. An incorrect pattern produces no metrics. | Tune retention, redact sensitive logs, use governed notification endpoints, and test alarms regularly. |
| `outputs.tf` | Exposes the IDs and URLs needed for the lab and helper. | Computed endpoint URLs, issuer, `sensitive` client secret. | Use `terraform output -raw NAME` for shell exports. Sensitive outputs are still available to authorized state readers. | Minimize secret outputs in production and consume secrets through a dedicated secrets workflow. |
| `terraform.tfvars.example` | Shows a safe input-file shape without becoming the active secret-bearing file. | Copy to `terraform.tfvars`. | Terraform does not automatically load files ending in `.example`. | Never place a real password or email secret in the committed example. |
| `.gitignore` | Keeps state, plans, generated ZIPs, caches, and variable values out of Git. | Negated example-file rule. | `.gitignore` does not untrack files already committed. | Treat leaked state as a credential incident; rotate exposed secrets. |
| `.tflint.hcl` | Enables Terraform/AWS linting and narrowly suppresses the stale runtime-enum rule. | TFLint plugin version and rule override. | Re-enable the runtime rule after the AWS ruleset recognizes Python 3.14 and Node.js 24. Provider validation remains authoritative for schema support. | Never broadly disable lint rules to hide real findings; keep rationale beside each exception. |
| `lambda/jedi_python.py` | Returns the Jedi response and marks a supplied token ID used. | Lambda proxy response shape, case-insensitive header lookup, DynamoDB `UpdateItem`. | A missing `x-token-id` is allowed but not tracked. Check environment/table permissions on `update-failed`. | The current update can upsert arbitrary IDs; production should validate ownership/existence with a condition expression. |
| `lambda/sith_node.js` | Node.js equivalent of the Jedi route. | AWS SDK v3 command pattern and async handler. | The package relies on the runtime-included SDK. Handler is `sith_node.handler`. | Bundle pinned SDK modules for deterministic production builds. |
| `lambda/unused_token_detector.py` | Scans records, calculates age, and emits a stable `ALERT:` prefix. | Pagination via `LastEvaluatedKey`, timezone-aware timestamps, environment threshold. | Invalid/missing `issued_at` values are skipped and logged. A full scan can time out on a large table. | Replace scans with an indexed status/time query at scale and avoid logging unnecessary identity data. |
| `scripts/get_token.py` | Authenticates with the public client, records issuance metadata, and prints test commands. | `USER_PASSWORD_AUTH`, MFA challenge response, JWT payload decoding, DynamoDB `PutItem`. | It does not enroll TOTP. Complete initial enrollment first. The caller needs DynamoDB write permission. | JWT decoding here is display-only and does not verify signatures. Do not use decoded claims as a security decision. Avoid password environment variables on shared systems. |
| `README.md` | Deployment, test, teardown, architecture, security, and production quick reference. | Operator sequence and boundaries. | Follow the manual TOTP step before the helper. | Treat all sample identities and URLs as lab values. |
| `docs/STYLE-ANALYSIS.md` | Records what was learned from the original draft and why corrections were made. | Style continuity and dependency reasoning. | Re-read before refactoring into modules. | Prevents accidental reintroduction of broad or unused permissions. |
| `docs/RESOURCE-STUDY-GUIDE.md` | Resource-by-resource explanations. | Arguments, dependencies, failure modes. | Use it alongside `terraform plan`. | Highlights production deltas. |
| `docs/TROUBLESHOOTING.md` | Symptom-to-cause operational guide. | Terraform, Cognito, API, Lambda, detector paths. | Start at the first service boundary that fails. | Avoid pasting tokens/secrets into tickets or logs. |
| `docs/REFERENCES.md` | Official AWS, Terraform, and provider links. | Primary sources only. | Provider “latest” may move beyond the pinned version. | Review current docs before upgrades. |
